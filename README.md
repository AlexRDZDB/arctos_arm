# Arctos Arm

ROS 2 workspace for the Arctos 6-axis robot arm: robot description, Gazebo
simulation, MoveIt 2 motion planning and a pose-tracking controller. Everything
runs inside a Docker container.

| | |
|---|---|
| Container OS | Ubuntu 24.04 LTS (Noble), from `osrf/ros:jazzy-desktop-full` |
| ROS 2 | Jazzy |
| Simulator | Gazebo Harmonic (gz sim 8) |
| Motion planning | MoveIt 2, MoveIt Servo |
| Host | Developed on Ubuntu 24.04 LTS with an NVIDIA GPU |

## Packages

| Package | Purpose |
|---|---|
| [arctos_description](ros2_ws/src/arctos_description/README.md) | URDF, meshes and the scene (arm, table, AprilTag, camera). RViz and plain Gazebo launch files. |
| [arctos_moveit_config](ros2_ws/src/arctos_moveit_config/README.md) | MoveIt 2 configuration: planning groups, kinematics, joint limits, controllers. |
| [arctos_simulation](ros2_ws/src/arctos_simulation/README.md) | Gazebo simulation driven through ros2_control, connected to MoveIt. |
| [arctos_control](ros2_ws/src/arctos_control/README.md) | Carrot-on-a-stick pose tracking: plan and execute when far, MoveIt Servo when close. |

## Requirements

- Docker Engine with the Compose plugin
- An NVIDIA GPU with the
  [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
  `docker-compose.yml` requests the `nvidia` runtime, so the container does not
  start without it.
- An X11 display on the host, for the Gazebo and RViz windows

`docker-compose.yml` is written for a Linux host. It has not been set up for
Windows or macOS.

## Build the image

1. Create `.env` with your host user and group IDs, so files the container
   writes into the workspace belong to you:

   ```bash
   cp .env.example .env
   id -u   # put this in UID
   id -g   # put this in GID
   ```

2. Build the image (`arctos-ros:jazzy`):

   ```bash
   docker compose build
   ```

   Rebuild with the same command whenever the `Dockerfile` changes.

## Run the container

1. Let local containers open windows on your display. One way:

   ```bash
   xhost +local:docker
   ```

2. Start the container in the background and open a shell in it:

   ```bash
   docker compose up -d
   docker exec -it arctos-ros bash
   ```

   Run the `docker exec` line again for every extra terminal you need.

3. Stop it with `docker compose down`.

`ros2_ws` is mounted at `/workspace/ros2_ws`, so edits on the host are visible
in the container and build output survives a restart.

## Build the workspace

Inside the container:

```bash
cd /workspace/ros2_ws
colcon build
source install/setup.bash
```

Source `install/setup.bash` in every new terminal. ROS 2 itself is sourced
automatically.

## Launch the Gazebo tests

All commands run inside the container, after sourcing the workspace.

| What | Command |
|---|---|
| Arm in Gazebo, joints commanded on plain topics (no MoveIt) | `ros2 launch arctos_description gazebo.launch.py` |
| Arm in Gazebo, controlled with MoveIt from RViz | `ros2 launch arctos_simulation gazebo_moveit.launch.py` |
| Pose-tracking demo: the arm follows a figure eight | `ros2 launch arctos_control carrot_demo.launch.py` |

Each launch starts its own Gazebo, so run one at a time.

- **MoveIt in Gazebo:** in RViz, drag the end effector marker in the
  MotionPlanning panel, then press *Plan & Execute*. The arm moves in Gazebo.
- **Pose-tracking demo:** nothing to click. The arm plans towards the target,
  then switches to Servo and follows it.
- **Headless:** add `gz_args:="-r -s --headless-rendering empty.sdf"` to run
  Gazebo without its window, and `rviz:=false` (simulation and control
  launches) to skip RViz.

Without Gazebo:

| What | Command |
|---|---|
| Robot model in RViz with joint sliders | `ros2 launch arctos_description display.launch.py` |
| MoveIt with simulated (mock) hardware | `ros2 launch arctos_moveit_config demo.launch.py` |

## Repository layout

```
Dockerfile            image definition
docker-compose.yml    container settings (Linux host, NVIDIA GPU, X11)
.env.example          template for .env (UID/GID)
ros2_ws/src/          the ROS 2 packages
```

`ros2_ws/build`, `ros2_ws/install` and `ros2_ws/log` are generated by `colcon`
and are not tracked by git.
